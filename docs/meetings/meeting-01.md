## 二、议题与结论

### 议题 1：Alpha 范围冻结

**结论**：本期只做 P0 主链路——登录注册与个人主页、发布邀约、邀约广场、邀约详情、类型筛选、邀约状态（招募中/已满）、草稿暂存。

**不做**：私聊、点赞收藏、智能匹配、消息推送、支付。以上全部顺延到 v1.0，避免中期范围膨胀。

**依据**：需求规格说明书 `docs/SRS.md` 中 P0 用例；答辩只演示主链路，不演示未完成功能。

### 议题 2：技术选型

| --- | --- | --- | --- |
| 后端框架 | Python 3.12 + FastAPI + Uvicorn | 自带 OpenAPI 与请求校验，`TestClient` 便于接口测试 | 无 |

**ADR 记录**：以上决策已写入 `docs/architecture.md` 第 4 节（ADR-001 ~ ADR-007）。

### 议题 3：仓库规范与分支保护

1. 仓库由 A 创建并完成初始化：README、LICENSE、`.gitignore`、Issue/PR 模板、`CONTRIBUTING.md`。
2. `main` 开启分支保护：**禁止直接 push**、PR 必须至少 1 个 Approve、CI 必须通过、禁止强推。
3. 分支命名：`feature/<成员>-<模块>`，例如 `feature/b-publish`、`feature/c-square-ci`。
4. Commit 规范：`feat:` / `fix:` / `docs:` / `test:` / `chore:`；一个 Issue 至少一个 commit，提交信息带 Issue 号。
5. 所有变更走 PR，PR 描述必须写 `Closes #<issue>`，由非作者评审。

> 会议现场确认：A 已创建仓库并邀请全员；B、C、D 当场确认已加入。

### 议题 6：风险与兜底

1. **登录模块阻塞**：A 的 #2 未合入前，B 的发布/草稿接口用 `X-User-Id` 过渡（见 ADR-005），保证并行开发；#2 合入后统一替换。
2. **C 的 PR 较大**：广场前后端 + CI 在同一个 PR，要求 C 在 11-05 晚前提交可评审版本，避免最后一天堆积。
3. **内存存储限制**：重启丢数据，答辩演示前统一执行种子脚本；文档“已知限制”中说明。
4. **合并冲突**：按层拆文件（router/service/repository/schema），B 的发布与草稿各自独立文件；冲突由后合并者负责解决并知会对方。
5. **AI 辅助代码**：PR 描述中标注 AI 辅助范围，作者必须能逐行解释；评审时随机抽问。
